# 体感工坊 · 「别撞墙！」

一个跑在浏览器里的摄像头体感游戏，外加它背后那套可以拿来做别的游戏的小框架。

在线试玩：<https://qianglaile.dengjiabei.cn>（要用电脑上的 Chrome 或 Edge，和一个摄像头；第一次开摄像头时要下载约 14 MB 的识别库和模型。没有摄像头的话，出错卡片上有"用演示模式看看"）

- **「别撞墙！」**：一面开着洞的墙朝你驶来，在它到之前摆出洞的形状，穿过去；摆错了被撞下水。墙有人形的（24 个姿势），也有几何的（窄缝、钥匙孔、矮门、圆洞、偏门）。越往后越快、越严。
- **姿势实验室**：把"摄像头 → 骨架 → 数字 → 墙"这条线上的每一步摊开来看；摆个姿势就能存成一面新墙。
- **戳泡泡**：示例游戏，规则和画面各一个文件，加起来两百多行，照着它就能写自己的。

这是一个**用来学习的项目**。它用的技术都是公开的——Google 的 MediaPipe 姿态识别、Three.js、Canvas、Web Audio——代码、画面、文案、关卡全部是自己写的，没有用任何外部美术或音频素材。它是在分析了一个同类网站的技术原理之后做的（分析见 [`docs/tech-analysis.md`](docs/tech-analysis.md)），但不是那个网站的复制品。

摄像头画面只在你的电脑上识别，不会上传到任何地方（见[隐私](#隐私)）。

## 快速开始

需要：Node 22.12 或更新，Chrome 或 Edge，一个摄像头。

```bash
# 1. 装依赖。项目自带 .npmrc，走国内镜像。
#    如果你的终端设置了代理而镜像不需要代理，用下面这条绕开：
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy npm install
# （没有代理的话直接 npm install）

# 2. 准备识别库和模型（约 15 MB，下载一次就行）
npm run setup

# 3. 运行
npm run dev          # 打开 http://localhost:5188
```

第一次打开时浏览器会问能不能用摄像头，点"允许"。然后：

- 退后两三米，让全身进画面；光线亮一点；背后别站人。
- 屋子小、只照得到上半身也行——游戏会发现看不到腿，只出上半身做得了的墙。
- 开局前它会提醒"往后退一点""往左站一点"之类。照做最好；做不到就站着别动，过几秒它按现在看得到的范围开始。
- 没有摄像头？出错的卡片上有"用演示模式看看"，由一个模拟出来的玩家替你玩。
- 游戏里的大按钮可以**举手悬停**来点：举起一只手，光标停在按钮上转满一圈就按下去了，不用走回电脑前。（只对真的摄像头有效：演示模式、用录制代替摄像头时不启用——不然回放到一个举着手的姿势，按钮就自己被点了。）
- 游戏中右上角有"暂停"和"设置"。在设置里换了识别模型或摄像头，识别会重启一下——关掉设置、点"继续"，重新站好之后，接着刚才那一局玩，分数和命都在。
- 家里人多、常有人从镜头前走过？在设置里打开"同时识别两个人"（见下面"旁人入镜"）。
- 首页背景里那个自己在闯关的小人是模拟出来的演示，没有用摄像头。

## 地址栏开关

写在地址最后，比如 `http://localhost:5188/#/play/wall?sim=auto&seed=7`。

| 开关 | 作用 |
|---|---|
| `sim=auto` | 不用摄像头，模拟玩家自动照着墙摆（演示、自动化检查） |
| `sim=wrong` | 模拟玩家一直站着（看撞墙和结算） |
| `sim=manual` | 模拟玩家站着不动；闯关时按 `P` 摆出当前这面墙、按 `S` 站好 |
| `seed=7` | 固定随机数种子：出墙顺序完全一样 |
| `only=<id>` | 只出这一面墙，反复练（实验室的"试试这面墙"用的就是它） |
| `fast=1` | 墙速 ×3，测试时不用干等 |
| `debug=1` | 右下角显示识别帧率、单次耗时、用的 GPU 还是 CPU |
| `worker=0` | 识别留在主线程，不放进 Web Worker（对比性能、排查问题） |
| `e2e=1` | 把内部状态挂到 `window.__mw`，供脚本和控制台查看 |

## 它是怎么工作的

从摄像头到游戏是一条六层的流水线，每一层只做一件事，对应 `src/engine/` 下的一个目录：

| 层 | 目录 | 输入 → 输出 | 关键文件 |
|---|---|---|---|
| 1 采集 | `camera/` | 摄像头 → 视频帧 | `camera.ts`：打开摄像头，把各种失败翻译成人话 |
| 2 识别 | `vision/` | 视频帧 → 每个人 33 个关键点 | `poseDetector.ts`（加载模型、GPU 不行退回 CPU）、`poseWorker.ts`（在 Web Worker 里跑）、`autoModel.ts`（跑不动就换轻量模型） |
| 3 追踪 | `tracking/` | 关键点 → 稳定的、同一个人的关键点 | `selectPerson.ts`（认准玩家，不让旁人顶替）、`oneEuro.ts`（一欧元滤波：静止时稳、快动时跟手） |
| 4 身体模型 | `body/` | 图像坐标 → 以米为单位的骨架 | `metric.ts`（换算成米）、`bodyModel.ts`（19 个关节、脚踩地、半身模式）、`profile.ts`（量出你的肢体长度）、`pose.ts`（关节角 ⇄ 骨架） |
| 5 动作特征 | `motion/` | 骨架 → 强度和事件 | `features.ts`：活动量、侧倾、举臂、下蹲……以及跳、蹲、举手这类"发生了一次"的事件 |
| 6 游戏 | `src/games/` | 玩家状态 → 规则、画面、声音 | `wall/`、`bubbles/` |

把 2～5 层串起来的是 `player/playerTracker.ts`：每来一帧识别结果，它吐出一个 `PlayerState`（身体、动作特征、事件、身材）。**游戏只认识 `PlayerState`，不认识摄像头和识别库。**

再往上有两个"管流程"的类，都不依赖 React，可以直接读、直接测：

- `src/app/engineController.ts` —— 引擎的一生：建哪种姿态来源、什么时候算就绪、出错了怎么办、设置变了要不要重启、自动选哪个模型。页面里的 `useEngine` 只是订阅它。
- `src/games/wall/session.ts` —— 一局游戏的流程：站位引导 → 标定 → 开局 → 每帧把玩家喂给规则 → 结束；以及识别中途重启后怎么重新标定、接着玩。

想看这几块最少要怎么拼才能跑起来，读 `src/games/wall/Attract.tsx`（首页背景的自动演示）：模拟玩家 → 追踪器 → 一局游戏 → 3D 场景，八十来行，没有界面。

还有三处值得先知道：

- **姿态来源可以换**（`input/`）。摄像头、模拟玩家、录制回放三种来源接口相同，下游分不出真假。所以整局游戏能在测试里用模拟玩家跑完，也能把一段录下来的真人动作在测试里反复重跑（见下面"录一段真人动作来调参数"）。
- **换算成"米"**。识别模型给两组点：图像里的位置（准，但人离得远就变小）和以髋为原点的三维位置（单位是米、和远近无关，但手脚末端没那么准）。每一帧在两者之间拟合一个"缩放 + 平移"，把图像里的点换算到米。之后所有阈值——洞有多宽、手要举多高——都用实际尺寸，站远站近、大人小孩是同一把尺子。
- **识别和渲染分开走**。识别每秒二三十次，在 Web Worker 里；画面每秒 60 帧，在主线程。渲染时不直接用最新的识别结果（会一顿一顿），而是让显示用的骨架平滑地追过去（`PlayerTracker.sample`）。

### 坐标约定（全项目统一）

**舞台空间**，单位米：`x` 朝玩家右手为正（也是屏幕右边），`y` 朝上，`z` 朝观众为正。小人站在原点、面朝 `-z`，墙从 `-z` 驶来。地面 `y = 0`，标定时你站的位置 `x = 0`。

**肢体朝向角**（在正对着墙的那个平面里量）：`0°` 朝下，`90°` 水平朝身体外侧，`180°` 朝上；负值表示越过身体中线。

**左 / 右一律指玩家自己的左右**，不是画面的左右。

## 「别撞墙！」是怎么判定的

- **人形洞看角度，不看轮廓**。每个姿势是九段肢体（左右上臂、前臂、大腿、小腿，加脊柱）各自的朝向角。判定时逐段比较你的角度和目标角度，全部在容差之内才算摆对；另外你得站在洞的左右 0.26 米以内（标准难度）。
  为什么不直接拿身体轮廓去套洞：摄像头识别有抖动，人的身材各不相同，用轮廓会要么太严要么太松；角度和身材无关，容差也好讲清楚。
- **几何洞看身体有没有陷进墙里**。身体用十几个胶囊体表示，墙是一个标量场（洞内为负）；任何一个部位有两成以上陷进墙体就算撞。
- **容差**：40° / 32° / 25°（轻松 / 标准 / 挑战），随关卡收紧。腿和脊柱看这面墙用没用到它们：用到了（双脚分开、侧弯、下蹲……）收紧到一半，因为它们的活动范围小，"双脚分开"和"站直"只差十几度；只动手的墙，腿和身子大致站着就行，用完整的容差。
- **墙到的那一刻**取最近 0.25 秒的判定结果投票，避免某一帧的抖动决定成败。
- 墙驶来的途中一直在判，所以屏幕上能实时告诉你"左手没摆对"，小人身上不对的部位会变红。
- **看不到人，绝不扣命。** "看不到"包括两种：画面里没有人；有人，但人形洞要比的那几段肢体里看得清的不到两段（比如贴得太近，画面里只剩头和肩）——没法判就不判，屏幕上会提示"看不清你的手脚，退后一点"。
  - 墙驶来途中看不到人超过 1 秒：自动暂停；人回来半秒后继续。要是墙已经很近了，它会先退回去一段，留 1.5 秒让你重新摆好。手动暂停之后再继续，也一样先退回去。
  - 墙到了、这一刻却没看到人（走开了，或者识别丢了几帧）：不判，墙停在面前等。人马上回来就接着判；一直不回来就暂停。
  - 同一面墙第二次因为看不到人而停下：这面墙不算，直接换下一面——免得某个姿势恰好让识别跟丢时，游戏卡死在它上面。不算的墙不扣命，也不计入这一关的进度：光靠躲，升不了关，也拿不到升关的奖励分。
- **游戏中途识别重启了**：原来的标定作废，正在飞来的那面墙也作废（不扣命、不计数）；重新站位（站好别动一两秒）、倒数三下之后接着**同一局**，分数、命、关卡都不变。
  - 在设置里换了识别模型或摄像头：游戏本来就为了开设置而暂停着，它会一直停在暂停面板上，等你点"继续"才开始重新站位。设置面板开着的时候它不会自己标定——那时你人在电脑前，不在站位上。
  - 摄像头断了、你点了"再试一次"：识别回来之后直接进入重新站位，和刚开局时一样。
- 设置面板开着时按 Esc 只关面板；面板关了以后，Esc 才是"暂停 / 继续"。
- **旁人入镜**：默认一次只识别一个人（多找一个人每帧要多花十来毫秒）。只要一直跟着你，旁人怎么走动都没影响。万一跟丢了你、转而认出了旁人，游戏不会把他当成你——它只认回到你原来位置附近的人，其余时候当作"没人"而暂停。代价是：旁人还在画面里的话，可能得等他让开，才能重新认出你。
  设置里的"同时识别两个人"是另一种取舍：模型每帧把两个人都找出来，程序按"离上一帧最近"认定哪个是你，旁人在场也能一直跟住；代价是每帧多花十来毫秒。
- 这一局按全身开的、中途却走近到脚出了画面：提示"脚出画面了，退回原位"（看不见的腿不参与判定，不会因此判错）。

墙体本身是从同一个标量场里用 marching squares 描出轮廓、再拉成 3D 的（`field.ts` → `contour.ts` → `scene/wallMesh.ts`），所以你看到的洞和判定用的洞是同一个东西。

## 怎么加一面墙

**方法一：在姿势实验室里摆出来。** 首页 → 姿势实验室 → 起个名字 → 点"5 秒后存" → 走回去摆好姿势。数到 0 的那一下，你的姿势就成了一面新墙。然后可以：

- 点"试试这面墙"，游戏里只出它，马上知道好不好过；
- 在"图鉴"里改名、改难度层（1 最容易，4 是单脚平衡那一类）、开关"加入闯关"、删除；
- 点"复制成代码"，贴进 `src/games/wall/poses.ts`，它就成了内置的墙；
- "导出成文件 / 从文件导入"，在浏览器之间搬。

新墙存在哪：用 `npm run dev` 运行时写进 **`public/custom-poses.json`**（项目里的文件，一面墙一行，换浏览器也在）；作为静态站点运行时存在这个浏览器里。

**方法二：手写。** 一面人形墙就是一条数据，加在 `src/games/wall/poses.ts` 的 `POSES` 里：

```ts
{
  id: 'cheer', name: '加油', tier: 2, upperOk: true, say: '一手叉腰，一手举高',
  armL: [{ a: 45 }, { a: -30 }],        // [上臂, 前臂]：左手叉腰
  armR: [{ a: 160 }, { a: 175 }],       // 右手举过头
  legL: [{ a: 4 }, { a: 0 }],           // [大腿, 小腿]：自然站立
  legR: [{ a: 4 }, { a: 0 }],
}
```

`a` 是朝向角；`s`（可选，0～1）表示这段肢体朝着镜头、从正面看变短了多少，比如深蹲时的大腿。写完去实验室的图鉴看一眼像不像。

**方法三：几何洞。** 在 `src/games/wall/shapes.ts` 里用 `engine/util/sdf.ts` 的基本形状拼一个"洞内为负"的函数，再配一个能钻过去的示范姿势。

## 怎么加一个游戏

照 `src/games/bubbles/` 抄。一个游戏只做四件事：

1. 每一帧从 `engine.tracker.state` 读玩家——`body.skeleton`（米制骨架）、`body.image`（画面里的位置）、`motion`（强度）、`events`（事件），用哪个拿哪个；
2. 喂给自己的规则。规则单独放一个不碰画面的文件（`logic.ts`），这样能直接写测试；
3. 把规则算出的状态画出来（2D 画布或 3D 场景随你）；
4. 结束时给"再来一次 / 回首页"。

然后在 `src/games/index.ts` 的 `GAMES` 里登记一行，首页就多一个按钮。摄像头、识别、选人、滤波、模拟玩家、出错处理，都已经在引擎里了。

想知道某个动作该用哪个特征、阈值取多少：打开实验室的"实时"页，做一下那个动作，看哪根条在动、动到多少。

## 调参

「别撞墙！」影响手感的数都在 **`src/games/wall/tuning.ts`**，每个数旁边有一句话说明：

| 想改什么 | 改哪个 |
|---|---|
| 姿势要摆多准 | `angleTol`（第 1 关）和 `angleTolFloor`（最严） |
| 用到腿和脊柱的墙，对它们多严 | `COMMON.legSpineTol`（现在是一半） |
| 墙来得多快 | `approach`（第 1 关几秒）和 `approachFloor`（最快几秒） |
| 每升一关紧多少、快多少、多几面墙 | `COMMON.tolStepPerLevel`、`approachStepPerLevel`、`wallsBase`、`wallsMax` |
| 人要站多正 | `posTol` |
| 几何洞多"软" | `shapeSlack`、`COMMON.hitFrac` |
| 几条命、倒计时几秒 | `COMMON.lives`、`COMMON.countdownSec` |
| 给几颗星、每颗多少分、连过加多少 | `COMMON.threeStars`、`twoStars`、`starScore`、`comboBonus` |
| 多久看不到人就暂停，回来后留多少时间 | `COMMON.lostPauseMs`、`resumeLeadSec` |
| 开局前的站位引导多严 | `COMMON.framing` |

不在这个文件里的只有"内容"：姿势库（`poses.ts`）、几何洞的形状和尺寸（`shapes.ts`），以及"第几关出哪几层的造型、从第几关起出几何洞"那张表（`levels.ts` 的 `levelPlan`）。动作特征的阈值（蹲多深算蹲、跳多高算跳）在 `engine/motion/features.ts` 开头。

### 录一段真人动作来调参数

实验室的"录制"页把一段动作的关键点数据存成 JSON（只有数字，没有画面），也能在页面上回放骨架看一眼。拿它来**调参数**有两种用法。

**在页面上**：录完（或者载入一个录制文件）之后点"用这段代替摄像头"。从这时起，实验室和游戏里的引擎吃的都是这段录制（循环播放）——"实时"页照常出角度和特征，游戏照常判定。页面上方有提示条，点"换回摄像头"就恢复。

这个开关和这段录制都只在内存里：**一刷新页面就回到摄像头，没下载过的录制也跟着没了**。所以先把它存成文件——"下载 JSON"，或者提示框里的"下载这段录制"。调参数的一轮是这样的：改 `tuning.ts` → 页面刷新之后，到"录制"页的"回放"里选这个文件 → 再点一次"用这段代替摄像头" → 看结果。（用 `npm run dev` 时，有的改动只是热更新、开关还在，有的会让页面整个重载；以页面上方那条提示还在不在为准。）

**在测试里**：录制可以顶替摄像头，喂给同一条流水线。

```ts
import rec from '../../tests/fixtures/recordings/my-take.json';

const tracker = new PlayerTracker();
const replay = new ReplayPoseSource(rec as Recording);
replay.onFrame((f) => tracker.ingest(f));
while (!replay.done) replay.step(33);   // 一口气放完；每一步之后 tracker.state 就是那一刻的玩家
```

改了滤波或判定的参数，再跑一遍同一段数据，就知道结果变了多少（`recorder.test.ts` 里有一个完整的例子）。

## 性能（在写这个项目的电脑上实测）

Intel 集成显卡、无头 Chrome、1280×720 的画面：

| 配置 | 单次识别 | 说明 |
|---|---|---|
| 标准模型 · GPU · 主线程 | 约 20 毫秒 | 每次识别都卡住画面一下 |
| 轻量模型 · GPU · 主线程 | 约 15 毫秒 | |
| 标准模型 · CPU · 主线程 | 约 49 毫秒 | GPU 用不了时的退路 |
| 标准模型 · GPU · **Web Worker（默认）** | 25～35 毫秒 | 每秒 24～30 次结果；主线程不再被识别占住 |

- 放进 Worker 之后单次识别反而慢了十来毫秒（传帧、和渲染抢同一块显卡），换来的是主线程不用每次停下来等识别，而且用得起更准的标准模型。无头浏览器里量到的帧间隔中位数是 16.7 毫秒；真实屏幕上到底流畅多少，无头模式量不出来，这一条是推断。想对比就加 `worker=0`。
- 让模型同时找两个人，每帧要多花约 12 毫秒，所以默认只识别一个人。
- 模型选"自动"时，第一次打开会先用标准模型测一两秒：识别一次超过 50 毫秒就换轻量模型。量的是"识别一次要多久"而不是"每秒出几次结果"——后者还受摄像头帧率限制，光线暗时摄像头自己就慢，那不代表电脑慢。结论记在浏览器里，14 天后重测；没量出来（比如当时标签页在后台）就不下结论。
- 画质选"自动"时，识别只能用轻量模型或只能靠 CPU 的电脑，画面也用低画质（不开抗锯齿和阴影）。这个结论会记在浏览器里：识别重启的那几秒、以及不开摄像头的首页演示，都沿用上一次的结论，下次识别起来了再更新。

## 验证过什么，没验证过什么

**验证过的**（都能重跑）：

- `npm test`：近六百个单元测试，覆盖每一层的逻辑。整局游戏用模拟玩家在测试里跑：三档难度、带着和真实识别差不多的抖动，每面墙都照着摆的玩家一条命都不掉。
- `npm run e2e`：无头 Chrome 里十五个场景——
  - 对着打包后的站点：
    - 首页，背景的自动演示在跑、没有开摄像头（数的是页面向浏览器要摄像头的次数，得是 0）；地址里写了不存在的游戏。
    - 模拟玩家连过六面墙；连撞三次到结算。
    - 用一张真人照片当假摄像头，实验室量出的上臂角度对得上。
    - 实验室存墙 → 刷新 → 试玩 → 删除；录制回放、导出导入。
    - 用一段录制代替摄像头（摄像头的视频轨道确实关了；刚录的那一段在识别重启之后还下载得到），再换回来。
    - 游戏中打开设置换识别模型：识别重启 → 面板开着时不会自己重新标定 → 关掉面板停在暂停面板上 → 点"继续"重新站位 → 同一局接着玩，命数没变；设置面板开着时按 Esc 只关面板、暂停还在；再打开"同时识别两个人"。
    - 故意让每帧循环里的代码出错：页面换成出错卡片、旧的 3D 场景收掉，而不是画面僵住。
    - 示例游戏；拒绝摄像头授权后走演示模式。
    - 反复进出游戏 20 次：离开时 3D 上下文立刻释放，最后一次的画面照常。
  - 对着开发服务器：识别跑在 Worker 里；游戏照常能玩；存的墙写进项目文件、改名、删除；别的网站发来的写入和文件读不懂时的写入都被拒绝，而且页面上说得出为什么；两个存墙请求前后脚到，两面墙都在。
  - 这套检查对你电脑的影响：最后那个场景会改 `public/custom-poses.json`——改之前把它原样备份到 `e2e-out/`，跑完恢复；脚本要是中途被杀掉，下一次运行一开头会先恢复（这一条实际演练过：跑到一半连同服务器、浏览器一起强行结束，再跑一次，文件回到原样）。页面触发的"下载"一律被拦下，不会往你的"下载"文件夹里存文件。
- "换算成米"用真实模型的输出核对过：一张真人全身照，换算后的点和模型自己的三维点在正面上平均差 2 厘米左右。
- 整个项目的代码先后两次交给独立的 AI 审查者（不带写代码时的思路）从头读过。它们指出的会影响玩家的问题都已修掉：逻辑上的修正都配了测试，界面上的修正大多由端到端检查盖住；剩下没有自动化测试的是提示文字和音效。

**没有验证的**（需要你自己试）：

- **没有任何真人对着摄像头玩过它。** 容差、墙速、站位要求、过关时的吸附，这些"手感"是按同类游戏的数值和模拟玩家定的，真人玩起来是松是紧、哪个姿势别扭，要你试了才知道——然后去 `tuning.ts` 改。
- 真实摄像头的抖动只用带噪声的模拟数据代替过；滤波参数可能需要调。实验室的"录制"就是为这个准备的（见上面"录一段真人动作来调参数"）。
- 真人数据只有一张照片。跳、蹲、举手这些事件只在模拟数据上测过。
- 识别模型在真人身上会不会丢帧、蹲成一团时还认不认得出人，没法在这里试。游戏对"看不到人"的各种情况都有安排（见上面的判定一节），但这些安排只在模拟数据上验证过。
- 声音和语音播报在无头浏览器里听不到，只确认了代码不报错。
- "识别器卡死"的判断（交出去一帧，8 秒没有回音就报错；头一帧是热身，放宽到 30 秒）只用假的识别器测过。头一次识别在这台电脑的无头 Chrome 里实测要 7.8 秒；别的电脑上要多久不知道，要是你的电脑一打开就报"识别引擎停了"，把 `engine/input/cameraSource.ts` 开头的 `WARMUP_HANG_MS` 调大。
- 只在 Windows 上的 Chrome 里跑过。Edge 应该一样；Firefox、Safari、手机没试过。
- 旁人入镜、跟丢后不认错人的逻辑只有单元测试，没有真实画面验证。"同时识别两个人"也一样：开关本身验证过（开了之后识别照常工作），但手边只有一张单人照片，画面里真有两个人时跟得对不对，没法在这里试。
- 用录制代替摄像头：验证用的录制是对着那张静止照片录的。一段真人在动的录制放进游戏里是什么样，要你录了才知道。

## 隐私

- 摄像头画面只进两个地方：页面上的 `<video>` 元素，和本机的识别模型（主线程或 Web Worker）。**没有任何一行代码把画面或它的任何一部分发到网络上。**
- 识别库和模型文件都放在本站自己的 `public/` 下，这个项目的代码运行时不访问任何外部地址。
- 上面说的是项目自己的代码。**线上那个站点**（qianglaile.dengjiabei.cn）托管在 Cloudflare 上，而这个域名开着 Cloudflare 的"网站分析"（Web Analytics）：Cloudflare 会往页面里自动插一段它自己的统计脚本（来自 `static.cloudflareinsights.com`），上报页面访问量和加载速度。它不是这个项目的代码，统计的东西和摄像头画面无关；不想要，在 Cloudflare 后台把这个域名的 Web Analytics 关掉就没有了。自己用 `npm run dev` 跑、或者部署到别处时没有它。
- "录制"存下来的只有关键点的数字，没有画面，而且只在你点"下载"时才变成你电脑上的一个文件。
- 唯一会发出去的数据：用 `npm run dev` 时，"存成新墙"把那面墙的关节角（十几个数字和一个名字）发给本机的开发服务器，由它写进项目文件。这个接口只认这台电脑上的本页面和命令行发来的请求——就算用 `vite --host` 把服务器开到局域网上，别的机器也只能看，不能往项目文件里写。（它是靠"请求是不是从本机连过来的"来分辨的，所以别把开发服务器挂在隧道或反向代理后面公开出去：那样外面来的请求在它看来都是本机发的。Vite 默认不接受陌生域名的请求，得你自己在配置里放行才会走到这一步。）
